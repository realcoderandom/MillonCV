# 验证指南

本文档维护 MillonCV 的测试命令、验收范围与通过标准。环境安装见 [README](../README.md#setup)；单次验证结果应记录在 PR、提交说明或对应任务文档中。

<a id="commands"></a>

## 命令与范围

以下脚本均在仓库根目录执行，定义见 [package.json](../package.json)。验收时命令退出码须为 `0`，如有告警需一并说明。

| 命令 | 用途与验证范围 |
|---|---|
| `npm run dev` | 启动本地开发服务（实际地址以终端输出为准），仅用于交互调试，不作为验收结论 |
| `npm run typecheck` | 执行 TypeScript 严格类型检查 |
| `npm test` | 运行 Vitest 单元测试与包边界规则回归，全部用例须通过 |
| `npm run test:watch` | 开发期监听模式；交付前仍须运行单次 `npm test` 并记录结果 |
| `npm run test:e2e` | 自动构建并在 Chromium 桌面端与 390px 移动端运行完整浏览器回归（含 Vite 开发模式检查） |
| `npm run test:e2e:ui` | 启动 Playwright 交互式调试界面 |
| `npm run lint` | 运行 ESLint 静态检查与包边界检查（注意：警告不会自动令命令失败，须人工确认） |
| `npm run audit:deps` | 通过 npm 官方接口扫描全部依赖的安全公告；退出码为 `0` 表示本次未检出已知漏洞 |
| `npm run build` | 执行类型检查并生成 `dist/` 生产产物，但不替代交互与 PDF 验证 |
| `npm run preview` | 预览生产构建产物，用于手工核对发布效果 |

[Vitest](../vitest.config.ts) 运行在 Node 环境，覆盖各包的 `src/**/*.test.ts` 与 [tests/architecture](../tests/architecture) 中的包边界规则测试。[Playwright](../playwright.config.ts) 的业务 [E2E 回归](../tests/e2e) 基于生产构建产物执行，每个用例使用独立的浏览器上下文与本地存储；外部字体请求会被拦截，分页样本固定使用系统字体，避免网络波动影响测试稳定性。

[开发模式回归](../tests/e2e/development.spec.ts) 使用项目真实的 Vite 配置独立启动开发服务，依次验证空缓存冷启动、保留缓存重启、Paged.js 资源加载、编辑实时同步、懒加载编辑器及页面刷新，并断言全程无 Vite 报错、页面异常或本地 HTTP 错误。该测试使用 `4174 + Playwright parallelIndex` 端口（端口被占即报错），结束后自动关闭服务并清理临时缓存，不会干扰用户正在运行的开发服务。

[CI 工作流](../.github/workflows/deploy.yml) 运行于 Ubuntu 24.04、Node 24 与 npm 环境：PR 与 `main` 推送均会依次执行 `npm ci`、依赖审计、类型检查、单元测试、静态检查与完整 E2E（启动前自动执行含测试在内的类型检查与构建）。依赖审计中的 high / critical 漏洞将阻断流水线；仅 `main` 分支在全部检查通过后触发部署，HTML 报告与失败 trace / 截图保留 7 天。

构建检查与线上部署验证应分别记录：部署成功后需实际访问线上地址，确认编辑器加载与分页预览均正常，避免将“构建发布成功”等同于“页面可用”。

首次运行 E2E 前请先安装 Chromium：

```bash
npx playwright install chromium
npm run test:e2e
npx playwright show-report output/playwright/report
```

Linux CI 环境请使用 `npx playwright install --with-deps chromium`。Playwright 会自行启动 `127.0.0.1:4173` 预览服务并在结束后自动清理（端口被占时直接报错，不复用外部服务），测试报告与产物统一输出至已忽略提交的 `output/playwright/`。

## 按改动范围选择检查

常规代码改动须运行 `npm test`、`npm run lint` 与 `npm run build`；涉及编辑交互、存储逻辑或分页链路时，须补充运行 `npm run test:e2e`（已包含生产构建，可替代单独 `build`）。单元测试与所属模块就近放置，例如 [Markdown](../src/resume/markdown/__tests__)、[表单辅助](../src/editor/__tests__)、[状态与恢复](../src/state/__tests__) 和 [分页调度](../src/preview/pagination/__tests__)；包依赖约束见[架构测试](../tests/architecture)，浏览器交互回归见 [tests/e2e](../tests/e2e)。

| 改动类型 | 通过标准 |
|---|---|
| 编辑与 Markdown | 三模式往返完整保留正文、模块类型与各级 `id`，覆盖改名、空模块、同名条目、照片与子项目；表单键盘流、拖拽排序、复制、链接编辑、撤销 / 重做及输入法体验正常 |
| 保存与恢复 | 输入后立即切换模式、切换 / 新建 / 复制简历、导出或刷新均不丢末次输入且不串写；写入失败可重试，历史快照与连续删除撤销队列可用；旧版迁移同时覆盖主文档与全部历史容器 |
| 模板与布局 | 新旧模板渲染、切换与打印正常，文档与独立模板主题作用域互不污染，排序与主 / 侧栏切换无遗漏，刷新与重置行为一致 |
| 工作区 | 深浅主题、宽屏、极窄编辑区与 390px 手机端均可用；目录与条目拖拽、方向键导航、`Escape` 取消、跨页定位及焦点恢复符合约定 |
| 依赖与锁文件 | 在独立目录按 CI 的 Node / npm 版本执行 `npm ci`，再完成依赖审计、单元测试、lint 与完整 E2E，防止上级 `node_modules` 掩盖缺失依赖 |
| 分包与导入 | `@/` 别名在 TypeScript、开发服务、单元测试与生产构建中解析一致；懒加载编辑器与分页脚本资源正常加载；包边界 lint 与架构测试全部通过 |
| 分页与 PDF | 除自动化回归外，还须按下一节要求完成真实 PDF 文件人工核验 |

依赖审计固定指向 npm 官方 registry，以避免部分镜像缺少审计接口导致误判。当前 ESLint 与 TypeScript ESLint 依赖链仍引用 `minimatch@10`，[package.json](../package.json) 通过 `overrides` 将受影响版本提升至修复版本 `11`；后续升级工具链时应复核是否可移除该覆盖。

## 浏览器与 PDF 人工核验

验收排版或导出改动时，应基于示例数据启动开发服务或预览生产产物，并记录操作系统、浏览器版本、视口尺寸、模板、主题及字体加载或回退情况。项目暂未声明正式浏览器支持矩阵，测试结论仅适用于被测环境。

1. **覆盖关键模板与内容形态**：修改共享渲染或打印样式时，至少核验单栏（如经典）、现代双栏、技术精简及受影响的历史版式；测试样本覆盖单页、略超一页与 2–3 页，并按需包含中英混排、长链接、嵌套列表、`||` 左右对齐、证件照与子项目。
2. **核验分页状态机**：检查智能一页开关、超限回退多页、连续快速输入与切换、计算中及异常状态；确保仅发布最新分页结果，分页失败时阻断导出旧快照。
3. **检查真实 PDF 产物**：在浏览器打印弹窗选择 **A4、100% 缩放、关闭页眉页脚**（需要模板底色时开启背景图形）另存为 PDF。打开文件对照预览逐页核对页数、断行与内容完整性，确认无元素遮挡、漏字、意外空白页或工具栏残留，且正文可检索、链接可点击。

当前自动化 E2E 已覆盖以下核心场景：
- [recovery.spec.ts](../tests/e2e/recovery.spec.ts)：异常数据只读保护与原始 JSON 下载、修复后重试读取、旧技能分组迁移、防抖期间恢复快照、未知模板回退与未来主题覆盖保留、v1 快照迁移及旧模板别名识别。
- [editing.spec.ts](../tests/e2e/editing.spec.ts)：三模式往返与输入后立即刷新不丢字、多简历草稿隔离、含特殊分隔符标题及照片 / 子项目的 Markdown 备份导出与导入。
- [modules.spec.ts](../tests/e2e/modules.spec.ts)：删除经历与子项目后继续编辑并局部撤销、连续删除多条依次撤销、表单级统一撤销 / 重做、新建简历空白骨架、已填可选联系方式默认展开、子项目默认折叠与计数、模块标题 `Enter` / 字段 `Tab` / `Ctrl+Enter` 键盘流、顶部置顶添加、复制条目、手柄键盘排序、链接编辑与移除、`+ 至今` 快捷填充、联系方式温和提示、双栏表单切栏、编辑区底栏实时页数，以及自定义标题跨模式同步。
- [pagination.spec.ts](../tests/e2e/pagination.spec.ts)：三类代表模板使用最新分页快照打印并生成真实 PDF（通过桩记录打印快照并用 Chromium `page.pdf()` 校验文件头与页数，报告附带产物），以及分页失败时阻断旧快照导出。需注意自动化 PDF 校验不能替代人工检查中文可搜索性、链接跳转、视觉细节与原生打印弹窗。
- [performance.spec.ts](../tests/e2e/performance.spec.ts)：使用可控时钟验证真实 Paged.js 调用与 localStorage 写入次数，包括连续输入合并重排、版本重命名不触发重排、导出立即推动待办、旧分页不覆盖新结果，以及大历史数据下偏好更新复用序列化缓存（详细计数 JSON 附在 HTML 报告中）。这些计数断言不能替代低配设备上的帧率、长任务或输入延迟实测。

浏览器核验可手工或借助自动化工具完成。若使用 agent-browser 自建会话，应命名会话、保持 10 分钟空闲超时并在结束或中断时关闭；若附着用户已有浏览器，须设置 `--idle-timeout 0` 且不主动关闭，仅清理本任务产生的临时文件。

<a id="documentation"></a>

## 纯文档改动

仅修改文档时，核对内容与最新实现一致、检查相对链接、页内锚点、代码路径与命令依据，并运行 `git diff --check` 检查空白字符，无需额外重跑构建或生成测试报告。

<a id="results"></a>

## 记录验证结果

交付说明中应明确写清：基于哪个提交或工作区状态的改动范围、环境与工具版本、实际执行的命令与场景、通过或失败结果、报告路径以及未覆盖项。未执行的检查项需如实标明，不能以历史通过代替本次验证；长期文档中的能力说明仅在结论变化时更新，规则见[文档维护规范](../CONTRIBUTING.md#documentation)。
